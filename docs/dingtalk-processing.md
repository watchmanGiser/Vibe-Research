# 击球区整理运行说明

北京时间每天 01:00（含）到 08:00（不含）暂停原文与整理更新；其他时段每 10 分钟检查。原文在 08:00、08:10……00:50 采集，整理在 08:01、08:11……00:51 消费存档，错开一分钟让原文先入库。原文同步、去重、图片下载与发布由原文服务独立运行；生产整理服务以 `DINGTALK_USE_ARCHIVE=1` 消费它已验证的存档，只处理新增、实质变化或已到重试时间的内容。整理不再额外查询钉钉，上游采集临时失败不会阻断已入队内容；原文同步时间沿用真实存档，不伪造采集成功。

## 去重和状态

队列在 Nova 按群身份、规范化正文和真实图片字节的 SHA-256 建立内容指纹。空行、行末空白和图片临时引用地址不触发重复整理；数字、单位、标点及图片内容变化会产生新版本。原始存档不改写。

每个内容版本保存 `pending`、`running`、`retry_wait`、`done` 或 `failed` 状态，以及尝试次数、失败分类、下一次重试时间和最后有效结果。调用前原子写入 `running`；退出后再启动会将遗留执行记为中断，沿用已有次数并进入冷却。跨进程队列锁由 Linux flock 提供，进程退出后释放。

最多尝试三次（含首次）。首次失败后 30 分钟再试，第二次失败后 2 小时再试，第三次挂起。结构错误优先复用本机已识别文字或未通过校验的产物，最多进入一次格式修正任务，该任务的模型调用也占尝试次数；传输失败可在同一任务内使用剩余三次总额度，收到修正结果后关闭该阶段。纯缓存读取和校验不消耗额外尝试。修正仍不满足研报来源、原页文字或类型要求时挂起，不编造缺失信息。危险字段和复制原文等输出直接拒绝。

原图未下载完成时只等待资源恢复，不调用模型。单条整理失败保留它已有的有效摘要；旧摘要按其对应的历史原文版本校验，新结果按新原文校验。尚无历史版本的旧缓存按严格结构迁移，后续原文版本保存在私有产物目录。发布结果按同一内容指纹选最早来源的稳定代表，其余来源继续保留在原文存档和逐消息缓存中。其他成功消息仍可发布。未完成的新资料保留在原文及队列中，不用空摘要覆盖已发布页面。

## 上限和账本

| 环境变量 | 默认值 | 含义 |
|---|---:|---|
| `DINGTALK_MAX_SUMMARIES_PER_RUN` | 2 | 每轮需模型的消息数，含失败 |
| `DINGTALK_MAX_IMAGE_SUMMARIES_PER_RUN` | 2 | 每轮图片消息数 |
| `DINGTALK_MAX_RUN_MS` | 480000 | 整轮时限，含采集、下载、模型与发布 |
| `DINGTALK_MAX_JOB_ATTEMPTS` | 3 | 同一内容版本最多尝试次数，可调低 |
| `DINGTALK_RETRY_DELAYS_MS` | 1800000,7200000 | 两次冷却间隔 |
| `DINGTALK_DAILY_TOKEN_BUDGET` | 2000000 | 已报告用量达到阈值后停止新模型调用 |
| `DINGTALK_DAILY_CALL_BUDGET` | 24 | 每日模型启动次数上限，未知用量也占次数 |
| `DINGTALK_JOB_STATE_FILE` | 摘要文件加 `.jobs.json` | 持久队列 |
| `DINGTALK_USAGE_LEDGER_FILE` | 摘要文件加 `.usage.jsonl` | 用量账本 |

每日按北京时间划分。预算是在发起调用前检查的阈值；已经在执行的请求可能使已报告 Token 超过阈值。一次 Codex 启动仍可能对应多个上游请求，启动次数不等于中转平台请求数。

账本持续保存调用开始、用量与结束事件，只记录内容指纹、调用编号、模型设置、耗时、错误分类、请求编号和 Token 统计，不记录凭据、提示词、群原文或工具输出。按调用编号合并事件后统计，避免完成事件重复累计。

Codex 完成事件和 Responses API 的输入字段包含缓存读取。统一账本中把缓存从输入中拆出，总 Token 为原输入加输出。没有完成事件时标记 `unknown`；只收到部分完成事件的失败调用标记 `partial`。这些用量需与中转平台账单核对，不假设未知用量为零，也不推算未经确认的费用币种。

普通资料单次最多 180 秒，研报图片最多 300 秒；整轮剩余时间不足时不启动下一条。模型超时会终止本机进程组并等待清理。systemd 的 8 分钟总时限和 `KillMode=control-group` 提供额外兜底。本机终止无法证明中转上游已停止，已发生的用量仍由平台记账。

## 图片缓存和可选直接 API

识别文字按真实原图组合的指纹保存到摘要文件旁的 `.artifacts/`，分段结果也保留，避免格式修正或其他正文变更重复读取相同原图。只有实际读取原图的调用可以写入识别缓存，后续纯文字整理和格式修正不能覆盖原图识别文字。原页文字仍仅按原图可见内容整理，不冒称已取得整份研报。

默认继续使用已接通的 Codex CLI，并启用 `--json`。可显式指定 `DINGTALK_GPT_MODEL`、`DINGTALK_GPT_REASONING_EFFORT`，不读取或迁移 CLI 认证文件。

直接 Responses 接口已提供独立适配器。仅在明确设置 `DINGTALK_MODEL_TRANSPORT=responses`，并通过环境提供 `DINGTALK_MODEL_API_URL`、`DINGTALK_MODEL_API_KEY`、`DINGTALK_GPT_MODEL` 后启用；端点应为完整 `/v1/responses` 地址。适配器传入真实图片、要求结构化输出、返回 usage，并关闭隐式自动重试。实际启用前应完成中转平台的图片、结构化输出和用量兼容性验收；本地模拟接口测试不等于平台已经验收。默认调用研报原页解析，完整研报检索仍需独立来源定位，不以模型自行补写替代。

## 部署与验证

先备份 Nova 运行脚本、摘要缓存和服务配置。将脚本及两个新增模块整体安装，再安装服务 drop-in、重载用户服务，验证后恢复原有定时器；不覆盖原文存档、媒体目录或凭据。

相关检查：`node --check` 检查改动模块；`node --test scripts/test/dingtalk*.test.mjs` 验证去重、冷却、恢复、三次封顶、逐条发布、OCR 复用、字段修正、未知用量、缓存口径、每日预算及进程组清理。

## 夜间暂停

日历定时器显式使用 `Asia/Shanghai`，不依赖 Nova 的机器时区；不启用开机触发或错过任务追赶，重启发生在暂停期间也会等到08点后再运行。安装原文服务的 `schedule.conf`、整理服务的更新窗口配置，以及 `vibe-research-dingtalk-night-stop.{service,timer}`。

自动服务设置 `DINGTALK_ENFORCE_UPDATE_WINDOW=1`。`ExecCondition` 在夜间跳过整项服务；脚本入口、模型启动前、原文写入及发布前再次检查时间，并把在途调用时限裁到01:00。每天01:00的停止任务结束两项在途服务及其进程组，远端提交前也检查北京时间，阻止跨边界发布。正在执行的模型调用如中断仍沿用既有尝试次数和用量记录；已发布内容及存档保留，网页继续可访问。

08:00恢复采集时，原同步机制从上次成功同步时间继续补取新消息；08:01起整理继续检查新增或到期任务。未显式开启更新窗口的维护测试脚本不受该生产规则影响。

## 文档下载、预览与整理

原文发布独立识别 PDF、DOCX、DOC 的 HTTPS 链接（含 Markdown 文件名），自动下载到权限受限的文档缓存。
默认只接受当前群实际使用的 `pushmedia.oss-cn-beijing.aliyuncs.com`，新增来源通过 `DINGTALK_DOCUMENT_ALLOWED_HOSTS` 明确配置；拒绝跳转。
原文件按内容 SHA256 命名，正文与逐页预览同时包含原文件指纹和自身内容指纹，重新解析生成不同版本地址。缓存校验实际正文长度及全部派生产物内容哈希，先在临时目录完成解析，再原子提交文件、最后更新索引。下载失败持续退避，解析失败仍提供原文件下载；不记录签名 URL 或授权头。

PDF 优先用 OpenDataLoader PDF 提取带表格结构的正文，失败时回退 PyMuPDF；无文字页面使用中英 OCR。有内容的扫描页识别失败或识别为空时，明确显示未识别页码，保留预览并暂停该文件自动整理，避免缺页正文被当作完整资料。
Word 用独立 LibreOffice 配置转换 PDF 生成原排版预览，转换失败时 DOCX 可回退正文预览。
预览支持页面切换、正文和原文件下载，完整 PDF 可在新窗口查看。文件正文不拼入原始消息字段，原始链接照常保留。

原文服务每轮默认处理4份文件（`DINGTALK_MAX_DOCUMENTS_PER_RUN`），后续轮次补齐历史文件。
单文件最大40 MiB、PDF最多200页、逐页图片最多100页，超过图片上限时界面标明原文件总页数，完整预览仍可用。
解析正文最多200万字符；整理输入超过20万字符时保留原文件和预览，等待人工分段。
文档缓存路径由 `DINGTALK_DOCUMENT_CACHE_DIR` 指定，解析解释器由 `DINGTALK_DOCUMENT_PYTHON` 指定。
解释器需安装 `pymupdf`、`python-docx`、`opendataloader-pdf`，并提供 Java、LibreOffice、Tesseract及`chi_sim`/`eng`语言包。

原文先上传文档文件再原子发布快照；公开缓存只暴露受校验的文件名，索引保持私有。
整理只读取已解析文档；全部文档成功解析后才调用模型，不能只依据文件名生成摘要。
原文件和解析正文的指纹均进入整理任务身份及分段缓存，同一文档复用缓存，正文变化后重新整理。
整理沿用现有逐条发布、运行时限、每日预算、重试次数和北京时间夜间暂停。

文档整理的模型只生成分类、来源、概述和要点，不重复抄写文件正文；研报原文摘录由程序从已解析正文取前2000字符附上，全文保留在正文预览中。附图识别缓存只接收实际图片识别文字，不以文件摘录替代。
